OPENAI USAGE / ARCHITECTURE AUDIT — NEXT TOKEN OPTIMIZATION PHASE

IMPORTANT:

Do NOT make broad architectural changes in this task.

We have already completed major token/cost optimizations including:

- deterministic Market Alerts (zero OpenAI)
- Risk Analyzer hybrid architecture
- Portfolio Analyzer hybrid architecture
- shared deterministic Risk/Portfolio Intelligence
- compact downstream AI contexts
- dependency fingerprints / SKIPPED_UNCHANGED
- recent-run guards / SKIPPED_RECENT
- Company Monitor discovery gate
- Investor Watch discovery gate
- cheaper web-search context
- deterministic portfolio performance
- OpenAI usage tracking

The next goal is NOT simply "use fewer tokens".

The goal is:

USE OPENAI ONLY WHERE IT ADDS REAL INTELLIGENCE.

We now need a complete audit of every remaining OpenAI call in the CURRENT CODEBASE before deciding what to optimize next.

3. IDENTIFY WHAT EACH AI CALL IS ACTUALLY DOING
==================================================

For each AI call split its responsibilities into:

DETERMINISTIC TASKS

Examples:
- calculations
- sorting
- filtering
- threshold comparison
- date calculations
- ranking using known numeric rules
- portfolio weights
- exposure calculations
- detecting exact structured state changes

QUALITATIVE / AI TASKS

- connecting multiple developments
- investment thesis reasoning
- assessing uncertainty
- qualitative company analysis
- opportunity reasoning
- decision reasoning

Anything deterministic should be flagged as a candidate for backend processing.

Do NOT automatically move it yet.


==================================================
4. LOOK FOR AI RE-ANALYZING AI
==================================================

This is especially important.

Identify situations where:

Module A uses OpenAI
→ produces structured interpretation
→ Module B sends essentially the same information to OpenAI again
→ Module C may interpret it yet again.

For example inspect flows such as:

News
→ Company
→ Opportunity
→ Trade Decision

Market
→ Risk
→ Portfolio
→ Trade Decision

Events
→ Company
→ Opportunity
→ Trade Decision

We EXPECT multiple reasoning stages where they answer genuinely different questions.

That is fine.

But identify where OpenAI is merely rephrasing, reclassifying or rediscovering something already established upstream.

Do not remove legitimate layered reasoning.


==================================================
5. AUDIT CONTEXT DUPLICATION
==================================================

For each remaining AI prompt inspect exactly what is sent.

Find duplicated information such as:

- same company fact appearing in Company Context + News Context
- same event appearing in Event + Company + News
- same portfolio fact appearing in Risk + Portfolio + raw holdings
- same Price Context represented multiple ways
- full previous analysis when compact previous state is sufficient
- raw data plus deterministic summary of the same raw data

Report these.

Prefer one authoritative representation of each fact.
