NEXT OPTIMIZATION — OPENAI MODEL ROUTING MIGRATION

We have now reduced unnecessary AI calls substantially and centralized
model routing.

The next objective is:

USE THE CHEAPEST MODEL THAT CAN SAFELY PERFORM EACH AI RESPONSIBILITY,
WHILE PRESERVING OR IMPROVING INVESTMENT QUALITY.

IMPORTANT:

This is NOT a blanket downgrade.

Trade Decision and Company Monitor are strategically important and should
remain strong unless there is a compelling reason otherwise.

We would rather:

remove unnecessary expensive calls
+
use cheap models for simple tasks
+
spend more on a small number of important reasoning calls

than use one medium model everywhere.


==================================================
1. INSPECT CURRENT CODE FIRST
==================================================

Inspect the actual current ai-model-config.ts and every caller using:

getModel(...)

Confirm all current model categories and module overrides.

Do not rely on previous task descriptions.

Produce the current mapping before modifying it.


==================================================
2. TARGET MODEL STRATEGY
==================================================

Evaluate the currently available OpenAI models supported by the API used
by this application.

Candidate model classes should include:

CHEAP / HIGH VOLUME
- GPT-5.4 nano class or equivalent

MID / QUALITATIVE
- GPT-5.4 mini class or equivalent

STRONG REASONING
- GPT-5.4 class or an appropriate current frontier model

Do not use Pro models for routine application calls.

IMPORTANT:

Do not blindly use the newest/most expensive model.

Match model capability to responsibility.


==================================================
3. DISCOVERY TASKS
==================================================

Discovery gates perform relatively simple work:

"Has anything materially changed that justifies an expensive analysis?"

Examples:

Company Monitor discovery
Investor Watch discovery
other lightweight discovery gates

These should use a CHEAP model.

Candidate:

GPT-5.4 nano

The discovery model should NOT perform the final investment analysis.

Its job is mainly:

change detection
relevance classification
materiality screening
structured extraction

Use reasoning effort NONE or LOW unless testing/code constraints indicate
otherwise.


==================================================
4. COMMAND BRIEF
==================================================

Command Brief / 20-second conclusion summarizes intelligence that has
already been produced by other modules.

It should not need the same model class as Trade Decision.

Candidate:

GPT-5.4 mini

Potentially nano only if its actual responsibility is simple enough.

Be conservative because Command Brief must still provide a useful overall
interpretation rather than mechanically concatenate statuses.

Initial preference:

GPT-5.4 mini
reasoning: none/low


==================================================

cross-asset reasoning
structured output
web-search-supported analysis

Initial preference:

GPT-5.4 mini
reasoning: low

==================================================
13. OPPORTUNITY FINDER
==================================================

Opportunity Finder is an important reasoning stage.

Its responsibility is:

"Given everything currently known, where are the interesting investment
opportunities?"

Initial candidate:

GPT-5.4 mini OR GPT-5.4 depending on actual prompt complexity.

Inspect its current workload.

If it receives a compact prefiltered candidate set and mainly ranks/
interprets candidates:

GPT-5.4 mini may be enough.

If it performs substantial cross-module investment reasoning across many
companies:

keep a stronger model.

Do not automatically downgrade.

Report the decision and rationale.

14. TRADE DECISION
==================================================

QUALITY PRIORITY.

Trade Decision is the central decision engine.

It combines:

Company analysis
Portfolio
Risk
Opportunities
Events/blockers
Price Context
Market
existing active decisions

and determines:

Hold
Watch
PrepareToBuy
PrepareToReduce
Buy/Ready
Sell/Ready

Use a STRONG model.

Initial candidate:

GPT-5.4

reasoning: medium or high depending on actual workload.

Do NOT use nano.

Do NOT use mini merely for cost savings.

This is one of the places where spending more per call is acceptable
because we have reduced call frequency elsewhere.

==================================================

unnecessary reasoning effort.
