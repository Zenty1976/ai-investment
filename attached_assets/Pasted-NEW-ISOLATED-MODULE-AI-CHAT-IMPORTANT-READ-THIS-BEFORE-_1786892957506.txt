NEW ISOLATED MODULE — AI CHAT

IMPORTANT: READ THIS BEFORE MAKING ANY CHANGES.

This task adds ONE NEW MODULE to the application.

DO NOT refactor, migrate, replace, modify, or "modernize" ANY existing OpenAI integration.

The application's existing OpenAI calls are working correctly and MUST remain exactly as they are.

This includes, but is not limited to:

- Command Brief
- Catalyst Intelligence
- Opportunity Finder
- Trade Decision
- Trade Review
- Company Monitor
- Risk Analyzer
- Portfolio Analyzer
- Market Monitor
- Sector Monitor
- Event Monitor
- News/Alert modules
- Automation Orchestrator
- all existing AI model routing
- all existing fingerprints/caching/token optimizations
- all existing prompts
- all existing callAi / callAiWithWebSearch infrastructure

DO NOT convert existing OpenAI calls to the Responses API.

DO NOT change existing Chat Completions calls merely because this new module uses a newer OpenAI interface.

DO NOT perform a project-wide OpenAI migration.

The Responses API + Conversations API architecture described below applies ONLY to the NEW AI Chat module.

If shared OpenAI infrastructure would require changing existing modules, create isolated infrastructure for AI Chat instead.

Existing behavior must remain unchanged.


==================================================
1. PURPOSE
==================================================

Add a new user-facing module called:

AI Chat

This should provide a normal conversational ChatGPT-style interface inside the
AI Investment application.

The user should be able to:

- type questions
- receive AI responses
- continue the conversation naturally
- see previous messages
- close the application
- reopen it later
- continue the same conversation
- create a New Chat
- reopen previous chats

Example:

User:
"Why is KEYS interesting?"

AI:
Explains the current KEYS situation.

User:
"But hasn't the stock already risen quite a lot?"

AI:
Understands that "the stock" refers to KEYS because this is the same persistent
conversation.

User:
"Compare it with Visa."

AI:
Understands the previous context and can retrieve current Visa data.


==================================================
2. OPENAI ARCHITECTURE — ONLY FOR THIS NEW MODULE
==================================================

For AI Chat ONLY, use the current OpenAI architecture:

OPENAI RESPONSES API
+
OPENAI CONVERSATIONS API

Do NOT use:

- Assistants API
- beta Assistants
- Threads
- Runs
- the old Assistant/Thread architecture

This new module should use OpenAI persistent Conversations together with Responses.

Again:

THIS DOES NOT MEAN EXISTING APPLICATION OPENAI CALLS SHOULD BE MIGRATED.

Responses + Conversations are ONLY for AI Chat.


==================================================
3. PERSISTENT CONVERSATION
==================================================

When the user creates a new chat:

Create an OpenAI Conversation.

Store the returned OpenAI conversation ID persistently in our own repository/database.

Conceptually:

localChatId
openAiConversationId
title
createdAt
updatedAt
lastMessageAt
archived

When the user sends another message in the same chat:

Use the SAME OpenAI Conversation ID with the Responses API.

Do not manually resend the complete historical conversation every time.

OpenAI Conversation state should provide the persistent conversational context.


==================================================
4. MUST SURVIVE APPLICATION / SERVER RESTART
==================================================

Do not store the conversation ID only in:

React state
browser memory
server process memory

Persist it.

After:

- page reload
- navigation
- frontend restart
- backend restart
- application restart

the user must still be able to reopen the chat and continue the conversation.

==================================================
7. CRITICAL: DO NOT AUTOMATICALLY SEND ALL MODULE DATA TO CHAT
==================================================

Do NOT do this:

Run All
    ↓
collect all module results
    ↓
push everything into AI Chat

Do NOT do this after Command Brief either.

Do NOT automatically append system snapshots to the OpenAI Conversation.

This is intentional.

Automatically pushing all module data would:

- waste tokens
- make conversations unnecessarily large
- store irrelevant data
- introduce stale snapshots
- potentially cause AI to use old data instead of current data

The Chat should retrieve application data ON DEMAND instead.


==================================================
8. READ-ONLY TOOLS FOR CURRENT APPLICATION DATA
==================================================

Give the NEW AI Chat module read-only tools/functions that allow the model to
retrieve current stored results from the existing investment modules.

The important principle is:

Conversation = conversational memory

Existing repositories = current factual application state

Web search = current external/public information


AI Chat should be able to retrieve relevant application state only when needed.

Conceptual read-only tools could include:

get_command_brief()

get_portfolio()

get_risk_analysis()

get_portfolio_analysis()

get_trade_decisions()

get_trade_review()

get_opportunities()

get_catalyst(ticker)

get_company_monitor(ticker)

get_price_context(ticker)

get_events()

get_market_alerts()

get_market_monitor()

get_sector_monitor()

get_news_monitor()

get_system_health()


Before implementing these, inspect the existing repositories/services and reuse
the existing stored module results.

Do NOT create duplicate analysis pipelines.


==================================================
9. READ CURRENT STORED RESULTS — DO NOT RUN MODULES
==================================================

This distinction is extremely important.

If AI Chat calls:

get_catalyst("KEYS")

it should READ the latest stored Catalyst Intelligence result.

It must NOT trigger Catalyst Intelligence analysis.

Likewise:

get_trade_decisions()

must read the latest Trade Decision result.

It must NOT run Trade Decision.

get_command_brief()

must read the latest Command Brief.

It must NOT regenerate Command Brief.

Opening or using AI Chat must therefore NOT accidentally trigger:

Run All
module updates
Catalyst analysis
Opportunity Finder
Trade Decision
Trade Review
Command Brief

The Chat is a consumer of existing state.


==================================================
10. EXAMPLE OF ON-DEMAND DATA ACCESS
==================================================

User asks:

"Why are we waiting on KEYS?"

The model should be able to determine that current application state is relevant.

It may call:

get_catalyst("KEYS")
get_trade_decisions()

Then answer using those current results.


User then asks:

"But hasn't the price already increased significantly?"

Because the Conversation remembers the previous discussion, the model understands
that the user is still talking about KEYS.

It may then call:

get_price_context("KEYS")

and answer.


User then asks:

"Compare it with Visa."

The model understands the context and may retrieve:

get_catalyst("KEYS")
get_catalyst("V")
get_trade_decisions()
get_price_context("KEYS")
get_price_context("V")

Only retrieve what is actually useful.


==================================================
11. READ-ONLY MUST REALLY MEAN READ-ONLY
==================================================

For the initial implementation, AI Chat MUST NOT have tools that can:

- execute a trade
- create an order
- approve a Trade Review
- modify portfolio holdings
- modify Catalyst state
- modify Opportunity Finder
- modify Trade Decision
- modify Trade Review
- modify Command Brief
- change settings
- change automation
- run modules
- trigger Run All
- write into investment repositories

AI Chat is initially an:

ANALYST
+
EXPLANATION INTERFACE

It can inspect the system.

It cannot control the system.


==================================================
12. CURRENT STATE VS CONVERSATION MEMORY
==================================================

Do not confuse conversation memory with current investment-system state.

Example:

Yesterday the user asks:

"Why are we waiting on KEYS?"

The Conversation remembers that discussion.

Today the user asks:

"What does the system think about KEYS now?"

The AI should NOT simply answer using yesterday's remembered module result.

Because the question asks about the CURRENT state, it should retrieve the latest
stored KEYS/Catalyst/Trade Decision data using the read-only tools.

Therefore:

OpenAI Conversation:
provides conversational continuity.

Application repositories:
provide current facts.

This distinction is fundamental to the design.


==================================================
13. COMPACT TOOL OUTPUTS
==================================================

Do not return enormous raw repository/debug objects to OpenAI unnecessarily.

Create compact Chat-specific tool responses containing the useful fields.

For example:

get_catalyst("KEYS")

might return:

ticker
company
eventType
eventDate
daysUntilEvent
opportunityState
catalystDirection
evidenceConfidence
expectationGap
priceAsymmetry
alreadyPricedIn
thesis
keyRisks
lastUpdated

Likewise Trade Decision should return the useful decision fields, not every
internal debug field.

This reduces token usage.


==================================================
14. WEB SEARCH
==================================================

AI Chat should also be able to use OpenAI web search through the Responses API.

This is separate from the application's stored module data.

Example:

User:
"Catalyst Intelligence says KEYS looks positive. Has anything new happened today
that strengthens or weakens the case?"

AI Chat may:

1. retrieve current stored Catalyst data
2. retrieve current Trade Decision
3. perform web search for current external information
4. combine those sources in its answer

The user should therefore be able to ask normal current-information questions,
not only questions about internal module results.


==================================================
15. MODEL SHOULD DECIDE WHEN TO USE TOOLS
==================================================

Do not call every read-only tool on every message.

The model should select relevant tools based on the user's question.

Examples:

"Hello"
→ no investment tools required.

"What does Trade Decision say about KEYS?"
→ Trade Decision / Catalyst tools likely required.

"What is happening with KEYS today?"
→ internal state + potentially web search.

"Explain what price asymmetry means."
→ probably no internal tool required.

"Compare KEYS and Visa based on our system."
→ retrieve relevant current data for both.


==================================================
16. TOOL-CALL LOOP
==================================================

Implement the normal Responses API tool-call flow for AI Chat.

Conceptually:

User message
    ↓
Responses API
    ↓
Model requests read-only tool
    ↓
Backend executes tool
    ↓
Tool result returned to same response/conversation flow
    ↓
Model may request another tool
    ↓
Final assistant response
    ↓
Save/render response

Support multiple tool calls if the model needs several pieces of information.

Add a reasonable safety limit so a single user message cannot create an
unbounded tool loop.


==================================================
17. WEB SEARCH VS INTERNAL DATA
==================================================

The assistant should distinguish between:

OUR SYSTEM SAYS:
information retrieved from the application's modules

and

CURRENT EXTERNAL INFORMATION:
information discovered through web search.

The answer should make this distinction naturally when relevant.

It must not pretend web information came from Catalyst Intelligence or vice versa.

==================================================
22. TOKEN / COST CONTROL
==================================================

Cost efficiency matters.

Design specifically to avoid unnecessary OpenAI usage.

Therefore:

- no automatic module-data dumps
- no module refresh caused by Chat
- no separate title-generation call
- no separate summary-generation call
- compact tool results
- only use web search when relevant
- only call internal tools when relevant
- reuse persistent Conversation state
- limit runaway tool-call loops

Expose token usage/debug information through the application's existing debug
mechanism if appropriate, but do not redesign the global debug architecture.


==================================================
23. SYSTEM PROMPT FOR AI CHAT
==================================================

Create a dedicated system/developer instruction specifically for AI Chat.

It should establish that:

- this assistant is the conversational analyst for the AI Investment application
- it can explain current module results
- it may retrieve current stored application state through read-only tools
- it may use web search for current external information
- it should use current tools rather than remembered old module state when the
  user asks about the current situation
- it must distinguish internal system conclusions from external web information
- it must not claim a trade is actionable unless Trade Review supports that
- Trade Decision remains authoritative for decision state
- Trade Review remains authoritative for actionability
- it cannot modify application state
- it should answer naturally and conversationally rather than dumping raw JSON


==================================================
24. DO NOT MAKE CHAT ANOTHER DECISION ENGINE
==================================================

AI Chat must not become an independent replacement for:

Catalyst Intelligence
Opportunity Finder
Trade Decision
Trade Review

If the user asks:

"Should I buy KEYS?"

the Chat can:

- explain what the system currently says
- retrieve relevant current module results
- retrieve external information if useful
- discuss the evidence

But it must clearly distinguish its conversational analysis from the application's
formal Trade Decision / Trade Review state.

Do not silently overwrite the system's decision hierarchy.
