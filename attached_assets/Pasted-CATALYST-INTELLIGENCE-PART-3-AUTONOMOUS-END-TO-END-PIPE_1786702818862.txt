==================================================
1. PRIMARY OBJECTIVE
==================================================

The system should work even when the user does nothing.

The desired behavior is:

MARKET UNIVERSE

→ discover upcoming potentially market-moving catalysts

AND

→ detect accumulating material signals

→ cheap screening

→ identify interesting candidates

→ create/reuse Company Driver Profile where necessary

→ targeted driver research where necessary

→ build/update Signal Accumulation

→ build CatalystFacts

→ deep Catalyst AI analysis ONLY when warranted

→ promote strong cases to Opportunity Finder

→ trigger/update Trade Decision when decision-relevant

→ surface result to user.

The user should NOT need to:

open a company
manually add it to Company Monitor
press Analyze
manually run Catalyst research

for this pipeline to work.

==================================================
4. AUTOMATIC DEEP ANALYSIS
==================================================

Currently verify whether a candidate identified by screening automatically reaches
deep Catalyst analysis.

If not, fix it.

The orchestrator/backend should automatically call deep Catalyst analysis when
the candidate satisfies eligibility rules.

Examples of eligibility:

- scheduled catalyst has sufficiently high potential impact
- screening result = INVESTIGATE/HIGH_INTEREST equivalent
- significant new driver signals appeared
- SignalAccumulation materially strengthened
- EventExpectationProfile materially changed
- event is approaching and previous analysis is stale
- important contradictory evidence appeared

Do NOT deep-analyze every discovered candidate.


==================================================
5. ESCALATION FUNNEL
==================================================

Use an explicit cost-controlled funnel.

LEVEL 0 — UNIVERSE

No OpenAI.
No web search per company.

Only compact instrument metadata.


LEVEL 1 — DISCOVERY

Prefer structured/cached information.

Identify:

upcoming events
existing material news/events
significant company/sector changes
possible emerging setups.

Very cheap.


LEVEL 2 — SCREENING

Backend deterministic logic.

PriceContext
event proximity
event importance
existing signals
company state if available
sector/market changes

No strong AI.


LEVEL 3 — TARGETED RESEARCH

Only candidates that passed screening.

Reuse existing intelligence first.

Perform driver-directed web research only for missing/material information.

Cheap model where appropriate.


LEVEL 4 — DEEP CATALYST ANALYSIS

Only serious candidates.

Use current centralized strong-analysis model routing.

Compact CatalystFacts only.


LEVEL 5 — PROMOTION

Opportunity Finder receives only relevant candidates.


LEVEL 6 — DECISION

Trade Decision receives material Catalyst opportunities only.


==================================================
6. DYNAMIC ANALYSIS DEPTH
==================================================

Do not treat every candidate equally.

A company with:

event in 27 days
+
weak evidence

should consume almost no expensive resources.

A company with:

event in 3 days
+
multiple independent material signals
+
attractive price asymmetry
+
new expectation changes

deserves deeper/fresher analysis.

Create configurable escalation logic based on:

daysUntilEvent
event potential impact
signal accumulation strength
evidence confidence
price asymmetry
expectation gap where available
new material evidence
previous Catalyst state

Do NOT use ticker-specific rules.


==================================================
7. AUTOMATIC RE-EVALUATION AROUND EVENTS
==================================================

This is critical.

For an interesting scheduled catalyst:

BEFORE event:
Catalyst Intelligence may produce:

HIGH_INTEREST
or
CANDIDATE_FOR_TRADE_DECISION.

WHEN event occurs:

the old pre-event thesis must NOT simply remain valid.

The event should trigger:

News/Event refresh
Company Monitor refresh
Price Context refresh
Catalyst refresh
Opportunity Finder refresh
Trade Decision refresh.

The system must then make a NEW post-event assessment.

Example:

PRE-EVENT:
positive thesis

↓

earnings/product announcement happens

↓

NEW DATA

↓

NEW assessment.

Do not execute an old planned trade based on stale pre-event assumptions.


==================================================
8. INTENTIONAL PRE-EVENT THESIS
==================================================

Preserve the distinction:

EVENT_BLOCKED

versus

INTENTIONAL_PRE_EVENT_THESIS.

An upcoming event must NOT automatically block a trade.

But it also must NOT automatically create one.

Catalyst Intelligence may tell Trade Decision:

"This opportunity exists specifically BECAUSE of the upcoming catalyst."

Trade Decision must then independently consider:

Catalyst evidence
price asymmetry
portfolio exposure
risk
position sizing
overall market
other opportunities.

Do not automatically create Buy/Ready from Catalyst HighInterest.
