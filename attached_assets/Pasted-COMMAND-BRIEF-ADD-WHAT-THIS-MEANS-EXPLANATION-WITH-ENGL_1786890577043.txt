COMMAND BRIEF — ADD "WHAT THIS MEANS" EXPLANATION WITH ENGLISH/DANISH LANGUAGE TOGGLE

IMPORTANT:

This should be a SMALL, isolated extension of the existing Command Brief.

Do NOT redesign Command Brief.
Do NOT change Catalyst Intelligence.
Do NOT change Trade Decision.
Do NOT change Trade Review.
Do NOT add another OpenAI call.
Do NOT translate the rest of the application.
Do NOT translate the existing Command Brief items.

The purpose is to add one short plain-language explanation below the existing
Command Brief so the user can easily understand what the brief actually means.


==================================================
1. ADD ONE NEW OUTPUT FIELD
==================================================

Extend the existing Command Brief output schema with one new field:

"whatThisMeans": "string"

This field should contain a short plain-language explanation of the overall
Command Brief.

It should NOT simply repeat or translate the bullet items word-for-word.

It should explain what the information means for the user in simple language.

Example in English:

"What this means: The system is cautious right now. Holding a large amount of
cash reduces market risk, but you may also miss potential gains. NVIDIA looks
interesting, while Serve Robotics remains risky. Tencent has a positive setup
ahead of earnings tomorrow, but the system wants to wait for the result before
reassessing it. There are currently no trades requiring your approval."

Example in Danish:

"Hvad betyder det? Systemet er forsigtigt lige nu. Din store kontantbeholdning
beskytter dig mod fald i markedet, men betyder også, at du kan gå glip af
kursstigninger. NVIDIA ser interessant ud, mens Serve Robotics fortsat vurderes
som risikabel. Tencent viser positive tegn før regnskabet i morgen, men systemet
vil vente på regnskabet, før aktien vurderes igen. Lige nu er der ingen handler,
du skal tage stilling til."

Keep it concise.

Target approximately 3–6 short sentences.


==================================================
2. LANGUAGE SETTING — ENGLISH OR DANISH
==================================================

Add a small language preference specifically for the "What this means" section.

Supported values:

ENGLISH
DANISH

Default:
ENGLISH

This preference affects ONLY:

whatThisMeans

It must NOT affect:

headline
items
actionStatus
JSON field names
system prompts
module names
Trade Decision wording
Catalyst wording
Opportunity Finder wording
any other UI text or AI output

Everything else must remain English exactly as today.


==================================================
3. TWO SMALL BUTTONS IN COMMAND BRIEF UI
==================================================

In the "What this means" section add two small compact language buttons:

EN
DA

or equivalent:

English
Dansk

Keep them visually subtle.

Do not redesign the Command Brief card.

Show which language is currently selected.


==================================================
4. LANGUAGE CHANGE MUST NOT TRIGGER ANALYSIS
==================================================

This is important.

Changing EN ↔ DA must NOT:

- call OpenAI
- rerun Command Brief
- rerun another module
- trigger Run All
- perform web search
- consume tokens

The button should ONLY save the preference.

The newly selected language becomes effective the NEXT time Command Brief is
naturally updated/run.

For example:

Current explanation is English.

User selects DA.

The currently displayed explanation may remain English.

No AI call occurs.

Next time Command Brief runs for any normal reason:

whatThisMeans is generated in Danish.

Likewise when switching back to EN.


==================================================
5. PERSIST THE LANGUAGE PREFERENCE
==================================================

Persist the preference so it survives:

page reload
navigation
application restart if existing settings storage supports this

Use the application's existing settings/preferences storage if one already
exists.

Do not introduce a large new settings architecture just for this.

Suggested setting name:

commandBriefExplanationLanguage

Values:

"en"
"da"


==================================================
6. PASS THE PREFERENCE INTO THE EXISTING COMMAND BRIEF CALL
==================================================

When Command Brief builds its existing OpenAI input, include the selected
explanation language.

For example internally:

explanationLanguage: "Danish"

or:

explanationLanguage: "English"

Then instruct the SAME existing OpenAI call:

"Generate the whatThisMeans field in Danish."

or

"Generate the whatThisMeans field in English."

IMPORTANT:

The rest of the OpenAI request and output remains English.

Do NOT translate the entire prompt into Danish.

The system prompt can remain English.

Only instruct the model that one specific output field must use the selected
language.
