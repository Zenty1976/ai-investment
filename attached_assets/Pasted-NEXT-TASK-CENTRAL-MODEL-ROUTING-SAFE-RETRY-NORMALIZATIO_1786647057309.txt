PART 2 — SAFE DETERMINISTIC RESPONSE NORMALIZATION
==================================================

The audit found that trivial schema formatting errors can cause an entire
expensive OpenAI call to run again.

Add a conservative deterministic normalization layer BEFORE deciding
that a full AI retry is necessary.

This layer may ONLY repair representation/format problems.

It must NEVER change investment meaning.


==================================================
SAFE NORMALIZATIONS
==================================================

Examples that MAY be normalized when the target schema makes the intended
representation unambiguous:

Enum casing:

"high" → "High"
"moderate" → "Moderate"

ONLY when exactly one allowed enum value matches case-insensitively.

Numeric strings:

"82" → 82

ONLY when the schema requires a number and the string is a valid finite
number.

Boolean strings:

"true" → true
"false" → false

ONLY where schema requires boolean.

Optional arrays:

null → []

ONLY where [] is a semantically valid optional/default representation.

Trim accidental whitespace around enum/string identifiers.

Do not broadly rewrite natural-language strings.


==================================================
NEVER NORMALIZE SEMANTIC INVESTMENT CONTENT
==================================================

The normalizer must NEVER change or invent:

Buy / Sell / Hold / PrepareToBuy / PrepareToReduce decisions

investment thesis conclusions

conviction

investmentCaseStrength meaning

risk conclusions

price targets

recommendations

company identity

event interpretation

position sizing

trade quantity

rationales

bull/base/bear conclusions

If these are invalid or missing, use the existing validation/retry logic.


==================================================
IMPORTANT ENUM SAFETY
==================================================

Even enums must only be normalized when it is purely representational.

Example:

"high" → "High"

is safe if High is an allowed enum.

But:

"Buy" → "PrepareToBuy"

is NOT normalization.

That changes meaning and is forbidden.
