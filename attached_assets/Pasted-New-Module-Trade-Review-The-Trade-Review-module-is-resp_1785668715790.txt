New Module: Trade Review

The Trade Review module is responsible for presenting the proposed trades generated by the Trade Decision module in a simple, user-friendly format.

Unlike the analytical modules, Trade Review must not perform any OpenAI analysis. It is purely responsible for transforming the decision output into concrete proposed trades that the user can review, modify and approve.

Trade Review is the final step before a trade is executed.

⸻

Responsibilities

Trade Review receives the latest Trade Decision result and converts it into a list of Trade Proposals.

Each proposal should contain only the information the user needs in order to decide whether to approve the trade.

Each proposal should display:

* Buy or Sell
* Company name
* Ticker
* Suggested number of shares
* Estimated trade value
* Very short explanation (maximum one sentence)
* Confidence
* Urgency
* Current status

The explanation must be extremely short.

Good examples:

Strong earnings and improved guidance.

Wait for upcoming earnings.

Improves portfolio diversification.

High valuation after recent rally.

High execution risk.

Do not display long AI explanations in this module.

If the user wants to understand why the proposal was created, they can open the Trade Decision module.

Trade Review should focus entirely on usability and speed.

⸻

Trade sizing

Trade Decision should no longer calculate or suggest an exact number of shares.

Instead, Trade Decision should return sizing guidance.

Add the following fields to every decision that could eventually become a trade:

targetAllocationPercent

maximumAllocationPercent

sizingConfidence

sizingReason

Example:

targetAllocationPercent = 5

maximumAllocationPercent = 7

sizingConfidence = Medium

sizingReason = Good diversification opportunity after earnings if catalyst is confirmed.

Trade Review should calculate the actual suggested number of shares.

The calculation should use:

* latest market price
* total portfolio value
* current holding
* target allocation
* available cash
* account currency
* FX conversion if necessary

This makes the calculation deterministic and repeatable while keeping the AI responsible only for the investment judgement.

⸻

Quantity adjustment

The calculated quantity is only a proposal.

The user must be able to:

* increase quantity
* decrease quantity
* type a custom quantity

Whenever quantity changes, immediately recalculate:

* estimated trade value
* resulting allocation
* remaining cash

This calculation should happen locally without calling OpenAI.

⸻

Trade status

Every Trade Proposal should have a status.

Initial statuses:

Waiting

Ready

Approved

Rejected

Future statuses:

Executed

Cancelled

The status should always be visible directly in the proposal list.

⸻

User actions

Each proposal should contain only a few simple actions.

Approve

Reject

Later

Details

Selecting Details should open the full Trade Decision analysis for that proposal.

⸻

Future automatic trading

Trade Review should already be designed for future autonomous trading.

The future workflow will be:

Trade Decision

↓

Trade Review

↓

User approval (or automatic approval)

↓

Broker execution

↓

Portfolio refresh

↓

Module refresh

For that reason, Trade Review should internally separate three independent concepts:

Decision

Approval

Execution

Execution is not implemented yet, but the architecture should already support it.

⸻

TradeProposal model

Introduce a dedicated TradeProposal model.

Trade Review should not work directly on the raw Trade Decision JSON.

Instead, convert decisions into TradeProposal objects.

Suggested fields:

id

decisionId

action (BUY / SELL)

ticker

company

quantity

estimatedPrice

estimatedValue

targetAllocation

confidence

urgency

shortReason

status

createdAt

approvedAt

executedAt

Trade Review should only work with these TradeProposal objects.

⸻

Changes to Trade Decision

Trade Decision remains the analytical decision engine.

Its responsibility is to answer:

“What should probably happen?”

Trade Review answers:

“What exactly should the user approve?”

Therefore remove presentation responsibilities from Trade Decision.

Trade Decision should no longer concern itself with:

* exact number of shares
* estimated trade value
* UI presentation
* approval workflow
* execution workflow

Instead, it should focus entirely on producing high-quality decision proposals together with sizing guidance.

⸻

Trade Review UI

The page should be very compact.

Each proposal should fit on a single card.

Example:

BUY

Novo Nordisk

12 shares

≈ 18,400 DKK

Strong earnings and improved guidance.

Confidence: High

[-] 12 [+]

Approve

Later

Reject

Details

The page should answer one simple question:

“What should I do today?”

The user should be able to review every proposed trade in less than one minute.

⸻

One additional improvement

I would also like one extra feature added.

Each Trade Proposal should include a calculated “Reason Score” from 0–100.

This is not another AI score. It is a backend-generated score based on how much evidence supports the proposal.

For example, the score can consider:

* How many modules support the proposal.
* Whether the Risk Analyzer agrees.
* Whether the Opportunity Finder agrees.
* Whether Company Monitor supports it.
* Whether Market Alerts support it.
* Whether an important event blocks the decision.
* The confidence returned by Trade Decision.
* The freshness of the underlying analyses.

This gives the user a quick indication of how well supported a proposal is without having to read the detailed analysis.

The Reason Score should be displayed as a small indicator on each proposal card and should also be available later if automatic trading is enabled.

This keeps the AI responsible for investment judgement, while the backend remains responsible for deterministic calculations and workflow. I believe this separation will make the architecture significantly cleaner, easier to maintain, and much easier to extend with automatic trading later.
